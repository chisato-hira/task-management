# AWS インフラ構成

このドキュメントは、本プロジェクトをAWS上にデプロイする際のインフラ構成・運用方針をまとめたものです。TerraformとAWS CLIを使ったコードベースでのデプロイを行っている。

> **このドキュメントの位置づけ**
> AWSアカウントの準備・Terraformによるインフラ構築（VPC・EC2・RDS）・アプリケーションのデプロイまで完了している。具体的な設定内容やコードそのものは`terraform/`・`deploy/`・`scripts/`配下を直接参照すること（設定値は変わりうるため、本ドキュメントには記載しない）。

## 1. 方針（決定済み・実装済み）

- 学習目的のため、EC2インスタンス1台＋RDSの最小構成でAWSとTerraformの基本を理解することを優先している
- リージョンは東京リージョン（`ap-northeast-1`）
- AWS無料利用枠の範囲内での運用を目指す構成にしている（NATゲートウェイ・ロードバランサー・Multi-AZ等は不採用）

## 3. 現在のAWSアカウントの状態（実施済み）

- **rootユーザーにはアクセスキーを一切発行していない**。プログラムからの操作は必ずIAMユーザー（またはIAMロール）経由で行う
- Terraform/AWS CLI専用のIAMユーザーに **AdministratorAccess** を付与している（グループ経由）
  - 本来は必要な権限のみに絞った最小権限ポリシーが望ましいが、個人の学習用途であるため現時点ではAdministratorAccessを許容している
- ルートユーザー・IAMユーザーともに**MFA（パスキー／セキュリティキー方式）を設定済み**
- AWS Budgets（予算アラート）を設定済み（想定外の課金を検知するため）
- ローカルの認証情報は `aws configure` で設定済み（リージョン: `ap-northeast-1`）
- ローカルにAWS CLI・Terraformをインストール済み

## 4. AWSサービス一覧

| サービス | 用途 | 無料利用枠の範囲 |
|---|---|---|
| VPC | 仮想ネットワーク | 常時無料 |
| EC2 | アプリケーションサーバー | 対象インスタンスタイプで無料（下記「運用」の注意を参照） |
| RDS | マネージドPostgreSQL | 対象インスタンスタイプ・ストレージ20GBまで無料（同上） |
| IAM | ユーザー・権限管理 | 常時無料 |
| Budgets | 予算アラート | 常時無料（一定件数まで） |

## 7. 実装ファイルの場所

| 場所 | 役割 |
|---|---|
| `terraform/` | インフラそのもの（VPC・EC2・RDS・セキュリティグループ等）をコードで定義。概念・用語は[Terraformガイド](aws-terraform-guide.md)を参照 |
| `deploy/nginx/` | EC2上のnginx設定（静的配信・リバースプロキシ） |
| `deploy/systemd/` | バックエンドを常時稼働させるsystemdユニット定義 |
| `scripts/deploy-backend.sh` | バックエンドのビルド・EC2への配置・再起動を行うデプロイスクリプト |
| `scripts/deploy-frontend.sh` | フロントエンドのビルド・EC2への配置・nginx反映を行うデプロイスクリプト |
| `backend/src/main/resources/application-prod.yml` | 本番用のDB接続情報（Spring Profileで有効化）。`.gitignore`対象のためリポジトリには含まれない |

## 8. EC2上のアプリ配置構成

デプロイスクリプトにより、EC2上の`/opt/app/`配下に以下が配置される。

```
/opt/app/
├── task-management.jar     # バックエンドの実行可能jar
├── application-prod.yml    # 本番用DB接続情報(Spring Profile)
└── frontend/dist/          # フロントエンドのビルド成果物(nginxが配信)
```

## 9. 認証情報の扱い

- RDSの接続情報（ユーザー名・パスワード）は、ローカル開発の`docker-compose.yml`と同じ値を使用している（利便性を優先した判断）
- 本番用の接続情報は`application-prod.yml`にのみ記載し、`.gitignore`で除外している
- SSH接続用の鍵ペアもリポジトリには含まれず、開発者のローカル環境（`~/.ssh/`）にのみ存在する

## 10. 機密情報の漏洩防止の仕組み（実施済み）

本リポジトリはGitHub上でPublic設定のため、Terraformコードを書き始める前に以下の多層的な対策を整備している。

- `terraform/.gitignore` で、tfstate・tfvars・SSHキーペア（`.pem`）などを追跡対象から除外
- `backend/.gitignore` で、`application-prod.yml`（RDSのパスワードを含む）を追跡対象から除外
- [gitleaks](https://github.com/gitleaks/gitleaks) をインストールし、`git commit` のたびに機密情報らしき文字列が含まれていないか自動スキャンするpre-commitフックを設定
  - フック本体は `terraform/hooks/pre-commit` としてリポジトリに含めている
  - `.git/hooks/pre-commit` は各自のローカル環境でGit管理外のため、新しい環境でクローンした際は以下のコマンドで手動リンクし直す必要がある
    ```bash
    ln -s ../../terraform/hooks/pre-commit .git/hooks/pre-commit
    chmod +x terraform/hooks/pre-commit
    ```
- GitHub側の secret scanning / push protection も有効（Publicリポジトリでは自動有効）

## 11. コマンドチートシート

```bash
cd terraform

terraform init      # 初期化(初回・プロバイダー追加時)
terraform plan      # 変更内容の事前確認
terraform apply     # 変更を適用
terraform output    # 出力値(EC2のIP等)を表示
terraform destroy   # 全リソースを削除
```

## 12. 運用

- 無料利用枠の期間・対象はAWSアカウントの作成時期によって制度が異なる場合がある（本アカウントでは`t2.micro`が無料利用枠対象外だった実績あり）。正確な内容は必ずAWSマネジメントコンソールの「請求とコスト管理」→「無料利用枠」で確認すること
- 学習が完了し環境が不要になった場合は、`terraform destroy` で作成したリソースを削除すること。EC2・RDSを起動したまま放置すると、無料利用枠の対象外になった時点から課金が発生する
